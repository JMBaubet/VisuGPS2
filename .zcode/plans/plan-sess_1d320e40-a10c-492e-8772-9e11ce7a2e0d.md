# Plan de réalisation — Import (Mode 1) & Édition (Mode 2) VisuGPS2

## Décisions prises avec vous
- **Périmètre** : Mode 1 (Import + pré-calcul keyframes) + Mode 2 (Édition/Montage). **Mode 3 (Relecture finale) exclu**. **§12 (améliorations V2) exclu**.
- **Étendue édition (phase 1)** : **Cœur = Overrides Caméra** + moteur de fusion + timeline + live preview + profile altitude + liste overrides. FlyTo/Messages/POI/Undo-Redo reportés à une phase 2 (le schéma de données les anticipe).
- **Pré-calcul** : **Variante A' (hybride lazy)** — déclenché au clic « Éditer », dans la map de la vue Édition qui sert aussi au live preview. Cache sur disque keyé par `traceId`. Fidèle au doc (`queryTerrainElevation`).
- **Résolution** : **résolution canonique 1920×1080** forcée pendant le pré-calcul (`map.resize()`), stockée dans les métadonnées, paramètres réglables. Lecture agnostique via `jumpTo` (le vidéoprojecteur révèle plus de contexte, ne décadre pas le traceur).
- **Backend Rust** : **nouveau module `src-tauri/src/edition.rs`** pour toutes les commandes d'édition/keyframes. `import_gpx.rs`, `settings.rs`, `gestionMode.rs`, `display.rs` **ne sont pas modifiés**.

## Commandes Tauri du nouveau module `edition.rs`

Toutes dans `src-tauri/src/edition.rs`, enregistrées dans `lib.rs::invoke_handler` :

| Commande | Signature | Rôle |
|---|---|---|
| `has_raw_keyframes` | `(app, traceId) -> bool` | Vrai si `keyframes/{traceId}_raw_keyframes.json` existe. |
| `get_raw_keyframes` | `(app, traceId) -> RawKeyframesFile` | Lit le fichier brut (ou erreur si absent). |
| `save_raw_keyframes` | `(app, traceId, file: RawKeyframesFile) -> ()` | Écriture atomique (tmp+rename) du fichier brut. |
| `get_montage_overrides` | `(app, traceId) -> MontageOverridesFile` | Lit overrides ; s'il n'existe pas, renvoie un fichier vierge `{overrides:[], messages:[], pois:[]}`. |
| `save_montage_overrides` | `(app, traceId, file) -> ()` | Écriture atomique du fichier d'overrides. |
| `delete_keyframes` | `(app, traceId) -> ()` | Supprime les 3 fichiers `keyframes/{traceId}_*.json` (cascade à la suppression d'une trace). |

Structs Rust miroir (dans `edition.rs`, dérivent `Serialize`/`Deserialize`) :
- `CamState { lng, lat, zoom, bearing, pitch }`
- `TraceurState { lng, lat, altitude }`
- `Keyframe { time, cam, traceur }`
- `ReferenceViewport { width, height }`
- `RawKeyframesFile { trace_id, total_duration, total_distance, reference_viewport, sample_rate, keyframes }`
- `OverrideParams { zoom?, pitch?, bearing?, zoom_offset?, bearing_offset?, pitch_offset?, speed_multiplier? }` (tous `Option<f64>`)
- `Override { id, name, start_time, end_time, params, easing, damping? }`
- `MontageOverridesFile { overrides, messages: Vec<()>, pois: Vec<()> }` (messages/pois anticipés vides).

Réutilisation du pattern de `import_gpx.rs` : `get_mode_dir`, écriture atomique tmp+rename, gestion d'erreurs en `Result<T, String>`.

## Milestones (ordre de réalisation)

### M0 — Fondations types & disque
- `src/utils/keyframes.ts` : interfaces TS fidèles au §7 du doc (mirrors ci-dessus).
- `src-tauri/src/edition.rs` : structs Rust + 6 commandes + helpers (`get_keyframes_dir`, atomic write).
- `src-tauri/src/lib.rs` : `mod edition;` + enregistrement dans `invoke_handler`.
- Types TS en miroir exact (snake_case, comme pour `TraceMetadata`).

### M1 — Store keyframes & navigation
- `src/stores/keyframes.ts` (Setup Store) :
  - State : `rawKeyframes`, `overrides`, `finalKeyframes` (computed), `currentTime`, `isPlaying`, `playbackSpeed`, `precomputeProgress`, `precomputeStatus`.
  - Actions : `loadForTrace(traceId)` (vérifie cache via `has_raw_keyframes`), `saveOverrides()`, `addOverride()`, `updateOverride()`, `removeOverride()`, `seek(time)`, `play()/pause()`.
- Route `/edition-camera/:traceId` + bouton « Éditer » câblé dans `Circuit.vue`.
- `EditionCamera.vue` : squelette de layout (toolbar home + nom trace + conteneur pour Map3D/Timeline/Panels) qui charge la trace au montage.
- `traces.ts::supprimerTrace` : après `delete_trace`, appeler `invoke('delete_keyframes', { traceId })`.

### M2 — Pré-calcul (Mode 1) ⭐ cœur technique
- `src/components/EditionCamera/Map3D.vue` :
  - Init map avec `style: mapbox://styles/mapbox/standard`, **`terrain: { source: 'mapbox-dem', exaggeration: 1 }`** + source `mapbox-dem` (`mapbox-terrain-dem-v1`, `tileSize: 514`, `maxzoom: 14`).
  - Lit le token via `settingsStore.getSettingValue('Systeme.Key.mapBox')` (même pattern que `Map.vue`).
- `src/composables/useKeyframeEngine.ts` — `precomputeKeyframes(map, geometry, opts)` :
  1. `map.resize(referenceViewport.width, referenceViewport.height)` (résolution canonique, paramétrable — défaut 1920×1080).
  2. **Échantillonnage** à `sampleRate` (100 ms) le long de la LineString : position traceur par interpolation linéaire sur la distance cumulée.
  3. **Altitudes** : `map.queryTerrainElevation([lng,lat])` par **lots de 50, délai 100 ms** entre lots (§8). Source primaire Mapbox, repli sur altitude GPX si `null`. Zoom de la map forcé ≥ 15 pendant les requêtes (cohérence des valeurs, note de bas de page du doc).
  4. **Dead zone** (§3 + §5.2) : `map.project(traceur)` → comparer `|offsetX|, |offsetY|` aux seuils (30 % du viewport canonique). Si débordement → nouveau `center` (position traceur), durée flyTo proportionnelle à la distance réelle (bornée `minFlyDuration`/`maxFlyDuration`), bearing lissé via `anticipationTime` + `bearingSmoothThreshold`.
  5. **zoomAltitudeFactor** : `zoom = defaultZoom + (altitude/1000)*0.5` pour éviter traversée relief.
  6. Produit les keyframes, écrit via `save_raw_keyframes`. Crée `montage_overrides.json` vierge (via `get_montage_overrides` qui retourne un vierge, puis `save_montage_overrides`).
- `PrecomputeOverlay.vue` : barre de progression (étapes : altitudes / dead zone / écriture) pilotée par callback de progression.
- Paramètres `settings.default.toml` sous `[EditionCamera.PreCalcul.*]` : `sampleRate`, `deadZoneX`, `deadZoneY`, `defaultZoom`, `defaultPitch`, `minFlyDuration`, `maxFlyDuration`, `speedFactor`, `anticipationTime`, `bearingSmoothThreshold`, `zoomAltitudeFactor`, `largeurReference`, `hauteurReference`. Entrée `[_meta.views.editionCamera]` pour le drawer.
- Paramètres `[EditionCamera.Traceur.*]` (§9.4) : `markerColor`, `markerSize`, `markerAltitudeOffset`, `showTrail`.

### M3 — Moteur de fusion (Blending) + Live Preview
- `src/utils/easing.ts` : `linear`, `smoothstep`, `easeInOut`.
- `blend(rawKeyframes, overrides) -> finalKeyframes` dans `useKeyframeEngine.ts` :
  - Pour chaque keyframe : trouver les overrides dont `[startTime,endTime]` contient `time`.
  - Appliquer valeurs absolues (`zoom`, `pitch`, `bearing`) et offsets relatifs (`zoomOffset`, etc.) sur la valeur brute.
  - **`center` jamais modifié** par override (règle §6.2).
  - Transition lissée par `easing` + `damping` sur les bords de plage (fenêtre ~500 ms).
  - `speedMultiplier` propagé dans le keyframe final.
- Recalcul automatique : `watch(overrides, …)` → régénère `finalKeyframes` (quasi instantané) → met à jour le live preview.
- **Live preview** : `map.jumpTo(cam)` à chaque déplacement du curseur ou frame de lecture, valeurs interpolées (LERP position, **SLERP bearing** pour éviter le tour complet par 0°).

### M4 — UI d'édition (Overrides Caméra)
- `Timeline.vue` : `v-slider` horizontal lié à `currentTime`, graduations **temps (HH:MM:SS)** et **distance (km)**, curseur synchronisé traceur. Raccourcis clavier (Début/Fin sélection, Espace play/pause).
- `AltitudeProfile.vue` : mini-canvas/SVG du dénivelé (X = distance, Y = altitude) ; clic pour seek.
- `OverridePanel.vue` — workflow §10.3 :
  - Sélection de plage (boutons « Début séquence »/« Fin séquence » ou champs `startTime`/`endTime` en `mm:ss`/`km`).
  - Sliders : zoom (10–20), pitch (0–85°), bearing (0–360°), speedMultiplier (0.25–2). Chaque mouvement → `map.jumpTo` immédiat (aperçu live).
  - Choix easing (list) + damping (slider 0–1).
  - Bouton « Appliquer l'Override » → `addOverride()` → sauvegarde + refusion.
- `OverrideList.vue` : panneau latéral listant les overrides (nom, plage, params), boutons **Activer/Désactiver** (toggle), **Éditer** (recharge les sliders + place le curseur), **Supprimer**.
- Repères visuels sur la timeline : zones colorées (jaune) pour les overrides actifs.

### M5 — Lecture (preview interne à l'éditeur, pas Mode 3)
- Boucle `requestAnimationFrame` dans `useKeyframeEngine.ts` : `play()` → avance `currentTime` selon `playbackSpeed` → `jumpTo` caméra interpolée + déplacement du marqueur traceur.
- Boutons Play/Pause + sélecteur vitesse (0.5x/1x/2x) dans `Timeline.vue`.
- Marqueur traceur (Point rouge, §9.4) déplacé à chaque frame, `markerAltitudeOffset` paramétrable (défaut 2 m). Orientation dynamique du marqueur **non implémentée** (§9.3 — explicitement hors périmètre).
- Trace déjà parcourue (`showTrail`) : LineString dynamique jusqu'au curseur.

## Points techniques notables

1. **Référence viewport canonique** : `map.resize(1920,1080)` avant `map.project()` dans le pré-calcul. Stocké dans `RawKeyframesFile.referenceViewport`. À la lecture, `jumpTo` reproduit le même cadrage géographique sur tout écran ; un vidéoprojecteur plus large ajoute du contexte périphérique sans décadrer.
2. **`queryTerrainElevation` exige terrain chargé** : on attend l'événement `map.on('idle')` + `'sourcedata'` du DEM avant de lancer les requêtes (sinon renvoie `null`). Zoom forcé ≥ 15 pour des valeurs cohérentes.
3. **Pas de Web Worker** : le pré-calcul reste async côté frontend (lots + `setTimeout`/`await`), l'UI reste réactive. Si profiling montre des blocages, on évaluera un worker en phase 2.
4. **Moteur de fusion côté frontend** : quasi instantané (la doc l'impose), pas besoin de Rust pour la refusion. Seules les écritures disque passent par Tauri (`edition.rs`).
5. **Réutilisabilité Map.vue** : on **ne modifie pas** `Map.vue` (accueil) — `Map3D.vue` est une map distincte avec terrain, dédiée à l'édition. Évite tout couplage et préserve l'existant.
6. **Suppression de trace** : `traces.ts::supprimerTrace` appelle `delete_trace` puis `delete_keyframes` (cascade). `import_gpx.rs` intact.

## Risques / à valider en cours
- **Précision `queryTerrainElevation` vs zoom** : on force le zoom ≥ 15 pendant les requêtes (note de bas de page du doc).
- **Taille des fichiers** : un trajet de 2 h à 100 ms ≈ 72 000 keyframes (2–5 Mo JSON). Acceptable ; on veillera à ne pas tout recharger en mémoire à chaque refusion (itération en streaming si besoin).
- **Écoute du `delete_trace`** : si suppression depuis une autre fenêtre (multi-écran), s'assurer que `delete_keyframes` est bien appelé dans `supprimerTrace` côté frontend (point unique de suppression, déjà centralisé dans le store).
