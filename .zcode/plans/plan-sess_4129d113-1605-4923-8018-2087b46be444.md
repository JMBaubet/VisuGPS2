# Refonte du SettingsDrawer : pilotage dynamique par `[_meta]` + multi-vues + accordéon + icônes criticité/surcharge

## Décisions arrêtées
- **Un seul TOML** (`settings.default.toml`), structure hiérarchique conservée.
- **Table `[_meta]`** au début du TOML = source de vérité pour l'organisation (vues, catégories, icônes, actions, handlers spéciaux). Inclut `Exemples` comme vue.
- **Drawer global** dans `App.vue`, réagit à la route active (`useRoute().name`).
- **Cas spéciaux** (Modes d'exécution = action, Moniteurs = carte double) déclarés dans `[_meta]` → zéro hardcodage dans le composant.

### 2.2 `src/composables/useSettingsTree.ts` (nouveau)
Composable centralisant toute la logique de construction de l'arbre d'affichage :

```ts
export function useSettingsTree() {
  const route = useRoute()
  const settingsStore = useSettingsStore()

  // Icône par défaut selon le type de paramètre (fallback si pas d'icône dans le _meta)
  const TYPE_ICONS: Record<string, string> = {
    int: 'mdi-numeric', float: 'mdi-decimal', bool: 'mdi-toggle-switch-outline',
    secret: 'mdi-form-textbox-password', list: 'mdi-format-list-bulleted',
    rgba: 'mdi-palette', material_primary: 'mdi-palette-outline',
    material_extended: 'mdi-palette-swatch', monitor: 'mdi-projector',
  }

  // L'arbre de catégories pour la vue active (système + vue courante)
  const categories = computed<CategoryNode[]>(() => buildCategories(
    settingsStore.meta, settingsStore.settings, route.name
  ))
  return { categories, TYPE_ICONS, ... }
}
```

`CategoryNode` :
```ts
interface CategoryNode {
  id: string                    // ex. "Carte.Traces"
  label: string                 // ex. "Carte — Traces affichées"
  icon: string
  params: ParamNode[]
  hasCritical: boolean          // remontée : au moins 1 param critique
  hasOverride: boolean          // remontée : au moins 1 param surchargé
  handler?: 'monitors' | null   // si groupe à handler spécial
}
interface ParamNode {
  def: SettingDefinition
  icon: string                  // def.icon ?? TYPE_ICONS[type]
  isCritical: boolean
  isOverridden: boolean
}
```

Logique de `buildCategories` :
1. Détermine les groupes à afficher = `meta.system.groups` ∪ `meta.views[routeName].groups`.
2. Pour chaque groupe, filtre `settings[]` dont le `path` commence par `<groupe>.` (ou, pour les groupes racine simples comme `Systeme`, par `Systeme.`).
3. Calcule `hasCritical`/`hasOverride` par OR sur les params enfants.
4. Résout label/icon depuis `meta.groups[id]` (fallback dernier segment du path).
5. Expose les `actions` système (modes) et les `handlers` (moniteurs) séparément pour le drawer.

### 2.3 Refonte `src/components/Accueil/SettingsDrawer.vue`
- En-tête `<v-list-item title="Paramètres">` conservé.
- **Section système** : rend les `actions` (Modes d'exécution → `openModes()`), puis les catégories système en accordéon. Pour un groupe avec `handler: 'monitors'`, l'item de catégorie ouvre `openMonitors()` (carte double) au lieu de lister les params individuels.
- **Section vue active** : rend les catégories de la vue en cours (`accueil` / `carte` / `exemples`).
- Chaque catégorie = `<v-list-group>` (accordéon Vuetify, repliable). L'en-tête du groupe affiche :
  - l'icône de la catégorie,
  - le libellé,
  - si `hasCritical` → un `<v-icon color="warning" size="small">mdi-alert-circle</v-icon>` en append,
  - si `hasOverride` → un `<v-icon color="info">mdi-circle-medium</v-icon>` (ou changement de couleur de l'icône de catégorie) en append.
- Chaque paramètre = `<v-list-item>` avec :
  - `prepend-icon` = `param.icon`,
  - couleur de l'icône = `warning` si `isCritical`, `info` si `isOverridden`, sinon défaut,
  - `append-icon` = `mdi-alert` si critique (tooltip "Critique") + `mdi-circle-medium` coloré si surchargé,
  - `@click` → `openParam(path)` (ou handler spécial).
- `openParam` / `openModes` / `openMonitors` conservés (ils ferment le drawer et ouvrent le bon dialogue).
- Les deux `<v-dialog>` (`ParameterCard` et `SettingsEditMonitor`) restent dans le composant.
- Contrôle par `appStore.isSettingsDrawerOpen` au lieu de `modelValue` (cf. 2.5).
