# Plan : Persistance des champs "favori" et "affichage" des traces

## Décisions validées
- **Pattern event-driven** : `Circuit.vue` émet `toggle-favorite`/`toggle-display` (id) → `CircuitsDrawer.vue` appelle l'action du store (cohérent avec `@delete`).
- **Commande Rust générique** `update_trace(id, favorite?, is_displayed?)` (réutilisable, conforme au pattern `settings::update_setting`).
- **Valeurs par défaut** : `favorite: false`, `is_displayed: false` à l'import.
- **Rétrocompatibilité** : `#[serde(default)]` sur les nouveaux champs pour ne pas casser le `traces.json` existant.

### 1.3 Ajouter la commande `update_trace` (après `delete_trace`, ~ligne 654)
```rust
#[tauri::command]
pub async fn update_trace(
    app: tauri::AppHandle,
    trace_id: String,
    favorite: Option<bool>,
    is_displayed: Option<bool>,
) -> Result<(), String> {
    let mode_dir = get_mode_dir(&app)?;
    let traces_path = get_traces_path(&mode_dir);
    let mut registry = load_registry(&traces_path);

    let trace = registry
        .iter_mut()
        .find(|t| t.id == trace_id)
        .ok_or_else(|| format!("Trace introuvable (id={})", trace_id))?;

    if let Some(fav) = favorite { trace.favorite = fav; }
    if let Some(disp) = is_displayed { trace.is_displayed = disp; }

    save_registry(&traces_path, &registry)?;
    Ok(())
}
```
Réutilise `load_registry` + `save_registry` (atomique). Paramètres `Option<bool>` → seuls ceux fournis sont mis à jour.

```ts
/**
 * Met à jour partiellement une trace (favorite, affichage).
 * Recharge la liste depuis le backend après mutation.
 */
async function updateTrace(
  traceId: string,
  patch: { favorite?: boolean; is_displayed?: boolean }
): Promise<void> {
  loading.value = true
  try {
    await invoke('update_trace', {
      traceId,
      favorite: patch.favorite ?? null,
      isDisplayed: patch.is_displayed ?? null,
    })
    await loadTraces()
  } finally {
    loading.value = false
  }
}
```
Exposer `updateTrace` dans le `return`.

## Note importante (rétrocompatibilité)
Les `traces.json` existants ne contiennent pas `favorite`/`is_displayed`. Grâce à `#[serde(default)]`, ils se chargeront avec `false`/`false` pour toutes les traces (aucune perte de données). Le prochain `save_registry` (au prochain import/suppression/update) écrira les nouveaux champs pour toutes les entrées.
